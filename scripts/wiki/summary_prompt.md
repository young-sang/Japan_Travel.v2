# 여행지 설명 요약 지시문 (D-089)

`scripts/wiki_destinations.py batches` 가 만든 묶음 파일 하나를 받아 한국어 이름과 설명을 쓴다.
같은 결과를 다시 만들 수 있도록 이 지시문을 그대로 서브에이전트에게 넘긴다.

## 입력

`scripts/wiki/batches/batch_NN.json` — 장소 배열. 각 장소의 칸:

- `qid` : Wikidata ID
- `pref` : 도도부현 (한국어)
- `ja` : ja 위키백과 문서 제목
- `kana` : 읽기 (없을 수 있음)
- `name` : 정해진 한국어 이름. `null` 이면 내가 정한다
- `source` : ja 위키백과 원문 (도입부 + 섹션, `【제목】` 으로 구분)

## 출력

`scripts/wiki/summaries/batch_NN.json` — `{ "<qid>": { "name": "...", "description": "..." }, ... }`. 입력의 모든 장소를 빠짐없이 쓴다. UTF-8, JSON 한 덩어리.

## 이름 규칙 (`name` 이 `null` 일 때만)

- 일본어 고유명은 국립국어원 일본어 표기법으로 적는다 (예: 清水寺 → 기요미즈데라, 東寺 → 도지, 嵐山 → 아라시야마). 읽기는 `kana` 를 따르고, 없으면 원문 첫 문장의 괄호 속 읽기를 따른다.
- 신사 · 절 · 성처럼 일본어 이름 안에 이미 종류가 들어 있으면 그대로 음역한다 (二条城 → 니조성, 平安神宮 → 헤이안 신궁).
- 괄호 구분어(「(京都市)」 등)는 넣지 않는다.

## 설명 규칙

1. **원문 안의 내용만 쓴다.** 원문에 없는 사실, 평가, 여행 팁을 더하지 않는다. 확신이 없으면 빼는 것이 맞다.
2. **길이는 500~1,000자(공백 포함).** 원문이 짧아 쓸 것이 없으면 그보다 짧아도 된다. 늘리려고 같은 말을 되풀이하지 않는다.
3. **숫자 · 연도는 원문에 있는 그대로.** 원문이 서기를 함께 적었으면 서기로 쓴다. 원문이 연호로만 적었으면(平成22年 등) 정확히 환산한 서기로 써도 된다. 그 밖의 환산 · 반올림 · 비교는 하지 않는다.
4. **구성**: 2~4 문단, 문단 사이는 빈 줄(`\n\n`). 첫 문단은 무엇이고 어디에 있는지(시 · 정 단위까지), 다음 문단부터 역사 · 볼거리 · 특징 중 원문에 많은 것. 소제목 · 목록 · 마크다운은 쓰지 않는다.
5. **빼는 것**: 주소 번지 · 영업시간 · 요금 · 가는 법 · 전화번호(S6 에서 따로 다룬다), 각주 표시, 「후술」 같은 원문 내부 참조.
6. **문체**: 평서문 "~다" 체. 사람 · 시설 · 지명은 표기법대로 한글로 쓰고, 처음 한 번만 필요하면 괄호에 한자를 붙인다.
7. 신앙 · 전설은 "~라고 전한다", "~라는 설이 있다" 처럼 원문의 단정 수준을 지킨다.

## 끝나면

출력 파일을 쓰고, 장소 수와 500자 미만으로 쓴 장소(원문이 짧았던 곳)만 짧게 보고한다.
