# 하이퍼 애자일 진행 규칙

졸업작품 보완 작업(2026-11-04~)을 이 규칙으로 진행한다. 정한 경위는 [D-071](DECISIONS.md#d-071--보완-작업은-하이퍼-애자일-규칙docsagilemd-으로-진행한다) · [D-072](DECISIONS.md#d-072--스프린트-안의-순서는-계획-승인--조각별-tdd--diff-자체-점검으로-한다) · [D-078](DECISIONS.md#d-078--데모회고의-코드-변경은-조각별-글-설명--주요-위치-파일줄-링크로-보여-준다).

핵심은 하나다. **스프린트가 하나 끝날 때마다 시연할 수 있는 상태를 유지한다.** 그러면 언제 멈춰도 그 시점의 결과물로 발표할 수 있다.

## 1. 리듬

| 항목 | 규칙 |
|---|---|
| 스프린트 길이 | 반나절에서 하루. 넘칠 것 같으면 범위를 자른다. 기간은 늘리지 않는다 |
| 동시 진행 | 한 번에 스프린트 하나만 진행한다 (WIP 1) |
| 릴리스 | 스프린트 몇 개를 묶은 단위. 끝나면 git 태그(`release-N`)를 찍고 push 여부를 묻는다 |
| 순서 | 아래 백로그의 우선순위를 따른다. 바꾸는 건 스프린트 사이에만 한다 |

## 2. 스프린트 안의 순서

```
0 준비 → 1 정찰 → 2 계획 → ⏸ 계획 승인 + 결정 게이트
      → 3 조각 반복 (Red → Green → Refactor → 확인 → 커밋) × N
      → 4 통합 검증 → 5 diff 자체 점검 → 6 기록 → 7 마무리 커밋 → ⏸ 데모 · 회고 · 승인
```

멈추는 곳은 두 군데(⏸)와, 진행 중에 새로 갈림길이 나왔을 때뿐이다.

### 0. 준비

- 이 문서의 백로그 항목과 관련된 DECISIONS 항목을 읽는다.
- `git status`가 깨끗한지 확인한다. 내가 만들지 않은 파일은 그대로 둔다.
- 백엔드(:8080)와 프론트(:5173)를 띄운다.

### 1. 정찰 (읽기만)

- 이번 범위의 코드, DB, 화면이 지금 어떤 상태인지 확인한다. **아무것도 고치지 않는다.**
- 숫자로 말할 수 있는 건 숫자로 남긴다(건수, 글자 수, 화면 개수 등). 데모 때 "전 → 후"를 보여 주는 근거가 된다.

### 2. 계획

다음 세 가지를 만든다.

1. **조각 목록**: 하나씩 끝까지 만들 수 있는 기능 조각들이다. 조각마다 **인수 기준**(무엇이 되면 끝인지)을 한두 줄로 적는다.
2. **하지 않을 것**: 한 줄로 적는다.
3. **결정 게이트 목록**: 정찰하다 보인 갈림길을 모두 모은다. 선택지는 2~4개, 추천안을 맨 앞에 두고, 선택지마다 무엇이 달라지는지 적는다.

### ⏸ 계획 승인 + 결정 게이트

- 계획을 보여 주고 결정 게이트 질문을 한 번에 묻는다. 그다음 멈춘다.
- 답을 받으면 그 자리에서 DECISIONS에 기록한다. 고르지 않은 안은 "기각"에 이유와 함께 적는다.
- 승인을 받아야 3단계로 넘어간다. 승인할 때 사용자가 조각을 빼거나 순서를 바꿀 수 있다.

### 3. 조각 반복 (TDD)

조각 하나마다 아래를 끝까지 하고 다음 조각으로 넘어간다. 계층별로 나눠 만들지 않는다.

| 단계 | 백엔드가 바뀌는 조각 | 화면만 바뀌는 조각 |
|---|---|---|
| **Red** | 인수 기준을 통합 테스트(`backend/src/test/...`)로 먼저 쓰고, **실패하는 것을 확인한다** | 인수 기준을 브라우저 확인 시나리오(경로, 동작, 기대 결과)로 먼저 쓰고, 지금은 그렇게 안 되는 것을 확인한다 |
| **Green** | 테스트를 통과하는 최소한의 구현(DB → API) | 시나리오를 만족하는 최소한의 화면 |
| **Refactor** | 테스트가 초록인 채로 정리 | 같음 |
| **확인** | 그 조각의 화면을 브라우저에서 확인 | 시나리오대로 브라우저에서 확인 |
| **커밋** | 조각 단위로 커밋한다. 중간에 멈춰도 끝난 조각은 쓸 수 있다 | 같음 |

- DB를 지우거나 바꾸기 전에는 반드시 백업한다(`data/*.bak_*`, CLAUDE.md DB 규칙).
- 진행 중에 새 갈림길이 나오면 **크기와 상관없이 멈추고 묻는다.** 변수명이나 파일 위치처럼 되돌리기 쉬운 것은 갈림길로 치지 않는다(DECISIONS의 "기록하지 않을 것" 기준).
- 범위 밖의 일이 보이면 손대지 않고 백로그의 "떠오른 것"에 적는다. 단, 이번 결과물을 망가뜨리는 버그라면 고친다.
- 조각이 생각보다 커지면 그 조각을 쪼갠다. 남는 부분은 다음 스프린트의 백로그로 보낸다.

### 4. 통합 검증 (완료 기준, Definition of Done)

- [ ] 백엔드 테스트가 모두 통과한다(`./gradlew test`). 테스트 수는 줄지 않고, 백엔드를 바꿨다면 늘었다
- [ ] 프론트 빌드(`npx vite build`)가 통과한다
- [ ] 모든 조각의 인수 기준을 브라우저(:5173)에서 다시 확인했다. 로그인이 필요한 건 `demo` 계정으로 본다
- [ ] 시드를 바꿨다면 `scripts/demo_seed.sql`을 다시 돌려도 결과가 같다

### 5. diff 자체 점검

`git diff <스프린트 시작 커밋>`을 다시 읽고 다음을 확인한다.

- [ ] 범위 밖의 변경이 없다
- [ ] 디버그 코드, 임시 파일, 주석 처리된 코드가 남아 있지 않다
- [ ] 주변 코드와 주석 밀도, 이름 짓는 방식이 맞다. 결정에서 나온 코드에는 `(D-NNN)` 주석을 단다
- [ ] CLAUDE.md의 "Do NOT Add" 항목(보안, 로깅, 성능 등)을 몰래 넣지 않았다

### 6. 기록

- DECISIONS: 이번 스프린트의 결정이 모두 들어 있는지 다시 확인한다.
- README: 실행 방법이나 계정이 바뀌었으면 반영한다.
- 이 문서: 백로그 상태를 바꾸고, 스프린트 로그에 한 줄을 추가하고, "떠오른 것"을 정리한다.

### 7. 마무리 커밋

기록 변경을 커밋한다. push는 하지 않는다.

### ⏸ 데모 · 회고 · 승인

다음 내용을 한 번에 보고한다.

1. **데모**: 조각별로 "전 → 후"를 보여 주고 증거(화면 캡처, 건수, 테스트 수)를 붙인다.
1-1. **코드 변경** (D-078): 코드 블록은 쓰지 않는다. 조각마다 다음 두 가지만 적는다.
   - **무엇을 했나**: 한두 문장의 글로 설명한다. 의도와 규칙(예: 점수 계산법, 동점 처리)을 적는다.
   - **주요 위치 1~2곳**: `[파일:줄](경로:줄)` 링크와 그 줄에서 무엇이 바뀌었는지 한 줄. 로직이 바뀐 곳(쿼리, 라우트, 테스트 시작점 등)만 고른다.
     import, 스타일, 문서만 바뀐 조각은 "코드 변경 없음" 또는 한 줄로 끝낸다. 나머지 변경 파일 목록은 적지 않는다.
2. **완료 기준 결과**: 통과하지 못했거나 확인하지 못한 항목은 그대로 밝힌다.
3. **회고 한 줄**: 다음 스프린트에 영향을 주는 사실을 적는다.
4. **백로그 변경 제안**: 새로 생긴 항목이나 순서 조정이 있으면 적는다.

그다음 멈춘다. 사용자가 "S다음 시작"이라고 해야 다음 스프린트의 0단계에 들어간다.

## 3. 커밋 · push

- 조각마다 커밋하고, 스프린트 끝에 기록 커밋을 하나 더 한다. 메시지 끝에는 관련 D 번호를 붙인다.
- 내가 만들지 않은 파일(`.agents/`, `.codex/`, `AGENTS.md` 등)은 커밋하지 않는다.
- push와 태그 push는 매번 묻는다.
